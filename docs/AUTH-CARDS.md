# 注册、每卡密码与独立安全页面

2026-10-13：登录、注册、安全中心统一为现有蓝白样式，使用本地 Base UI/shadcn 风格组件和 Motion。

## 当前用户流程

- `/register`：户名＋手机号＋验证码注册。只创建用户身份，不自动创建账户或银行卡，也不弹出设置交易密码。
- 注册完成可直接进入首页、查询和与 Agent 对话。账户页展示无卡状态及“申请新卡”入口。
- 申请银行卡：先选择储蓄卡/信用卡和备注，生成服务端确认单；点击确认后打开 `/secure-operation` 独立页面，为这张新卡设置两遍 6 位交易密码。确认成功后才发卡、建立零余额独立账户。取消设密不会发卡。
- **每张银行卡一个独立密码**。新卡不继承其他卡密码，A 卡密码不能用来验证 B 卡。安全中心与卡片管理都能单独修改该卡密码，修改要求短信、指纹或人脸验证（后两者为明确标注的演示）。
- 旧卡第一次升级时兼容复制原账户密码的哈希到各卡独立记录，余额、尾号和账单保持原关系。之后每张卡独立修改，不会联动更新其他卡。
- 查看卡号：默认显示尾号，点击透明背景灰色眼睛，调用独立验证页输入该卡密码；页面关闭后由调用方读取服务端验证结果，卡片展示完整16位卡号。30秒、离开窗口、切卡或收起面板后自动隐藏。
- 交易确认：最终黄色的常规转账可在独立页面任选付款卡密码、短信、指纹或人脸之一；UTC+8自然日跨本人所有账户累计含本笔严格超过1000元，或AA付款等基础红色操作，有卡时必须卡密码加额外强验证（短信或演示指纹/人脸）。无卡且不要求双重验证时使用强验证方式。单笔严格超过3000元或收款账户被标记 suspected 时，额外因子仅接受指纹/人脸。confirmed 高危账户继续拒绝。最终等级取原确认单与最新策略的较高者，不能信任前端声明。
- Agent 使用相同卡片、确认组件和独立安全页面。对话保持挂载，页面完成后读取银行回执；密码不经过 Agent、不进入工具参数或对话。`show_bank_card` 调出脱敏卡片，`card_password_settings` 调出指定卡的修改入口。重名先询问尾号。
- 密码页面统一由底部弹层呈现：顶部白条可下拉取消，关闭按钮/Escape 返回原界面；摘要来自银行确认单。验证提示为“请输入（尾号 xxxx）交易密码”，新卡未发号时提示设置新卡密码。密码框支持显隐、独立数字键盘、删除和收起，键盘展开时弹层向上扩展；超出可用高度时在独立页面内滚动。遵循系统减少动画设置。
- 常规转账可切换“使用其他方式验证”；异常转账只接受密码加指纹/人脸，不能用短信替代第二步。独立页面只向父页面报告布局高度及完成/取消通知，密码和键盘内容不跨文档传递。

## 实现地图

- `src/server/auth.ts`：注册仅创建用户，不自动发卡。`src/routes/index.tsx` 直接展示首页，取消原全局设密门禁。
- `src/server/cards/password.ts`：每卡独立 scrypt 哈希、旧卡兼容迁移、密码版本与错误次数熔断。
- `bank_card_passwords`：按 cardId、userId 保存独立哈希和版本。5次密码失败锁定账户30分钟，防止换卡继续猜密码。
- `bank_secure_requests`：短期安全请求，绑定登录用户、浏览器会话、用途、卡片及具体动作，记录状态和验证版本。设密凭据只存哈希，用后清除；完整卡号不存入结果表。
- `src/server/security/operation.ts` + `/api/secure-operation`：创建请求、读取安全摘要、提交验证、取消、读取结果。所有返回均 no-store；消息通知本身不是验证凭证。
- `src/routes/secure-operation.tsx`：独立文档中的设密、卡密码输入、短信/指纹/人脸方式切换与操作核对页面。
- `SecureSheet.tsx` + `CardPasswordInput.tsx`：Base UI/Motion 底部安全弹层和可复用密码输入/数字键盘；`SecureOperationProvider` 校验来源、会话请求标识后接收非敏感尺寸通知。
- `SecureOperationProvider`：在独立文档中打开页面，保留后方首页/Agent状态；只接收同源、匹配iframe来源和requestId的完成通知，然后向服务端查询结果。关闭或取消不会当作成功。
- `confirmPending`：重新评估风险，校验银行卡证明、版本和动作绑定，验证红色MFA，再一次消费证明与确认单。申请卡片时，密码哈希与新卡在发卡事务中绑定。
- `bank_card_numbers`：完整16位Luhn卡号加密保存，查询使用HMAC指纹；工具与首页只返回脱敏投影。原文财收款账号仍兼容，完整卡号＋户名也能查找收款账户。
- `CONFIRM_SECRET` 同时用于派生卡号加密密钥，部署须保持原密钥；轮换时先迁移卡号密文。
- 旧账户密码与修改凭证API保留兼容历史客户端和已有确认单；新界面和模型不再使用账户级密码修改工具。新流程不要求先设置账户级密码。

## 验证

- 自动回归：新用户无卡、取消不发卡、每卡密码隔离、改A卡不影响B卡、旧版本证明失效、会话/用户隔离、用途与动作绑定、防重放、过期与锁定；原风险标记、授权、AA和密码修改回归一并运行。
- 实际HTTP：注册 → 无卡浏览 → 申请两卡并设置不同密码 → 验证互不通用 → MFA改其中一张 → 老账户向新卡转账50元，付款卡密码＋短信强验证 → 双方余额/账单及重复提交核对。记录：`.scratch/per-card-proof.json`。
- 浏览器：注册后直接进入无卡首页；申请时进入独立设密页，取消返回原确认单且不发卡；查看卡号在独立验证页输入已设置的卡密码，关闭后原卡片获取结果；Agent复用相同流程。
- 全部测试使用独立库与本地模拟短信适配器，没有向真实手机发送短信，也未写入原用户数据库。
- 底部密码弹层实测：账户与 Agent 查看同一张卡；六位限制、数字键盘删除/收起、显隐、正确密码返回完整卡号、关闭取消、跨 iframe 下拉取消、原对话与卡片保留。每卡安全专项 7 项通过。截图：`.scratch/password-sheet.png`、`.scratch/password-sheet-keypad.png`。

## 2026-10-13 验证规则与参考图修订

- 常规验证的“使用其他方式验证”置于蓝色确认按钮下方，默认折叠；强验证直接显示指纹/人脸按钮，不再展示折叠入口。指纹/人脸为点击即通过的演示按钮，界面和审计明确标注，不采集生物特征。
- `AUTH_DEMO_MODE=true` 才能签发/使用演示凭据；默认生产环境关闭。凭据绑定用户、动作/安全请求、方式、5分钟有效期且一次消费。既有 WebAuthn 接口保留兼容，当前交易页面不显示 Passkey，也不能把它当作异常转账的指纹或人脸因子。
- `verification-policy.ts` 与 `confirmPending` 共同服从最终红色等级，不能用单笔双重验证条件覆盖基础风险或日累计升级。2026-10-14恢复赛题要求的日累计1000元规则；恰好1000元不因累计升级。收款人新旧与夜间金额规则仍未恢复，锁定、频率熔断和人工确认高危拒绝继续保留。扣款事务再次读取跨账户累计，旧黄色授权不能并发越线；定时任务风险升级后等待重新确认，已强验证的定期授权仍受原范围与额度约束。
- 卡号查看仍要求对应卡密码；新卡仍需两遍设密。验证方式切换不会把密码带入模型。
- 首屏绿色闪屏：独立页在 head 阶段标识文档，关键全局样式将 html/body 及空白区固定白底、浅色控件并关闭旧主题背景装饰；查询加载展示白蓝骨架，不展示旧绿主题。
- 专项覆盖3000元边界、三种替代方式、异常第二因子限制、动态风险升级、凭据用户/动作/方式隔离、重复提交、演示关闭拒绝。测试均使用 `.scratch` 独立库。
- 2026-10-14累计与最终验证修复验收：41个测试文件、435项通过；类型检查与生产构建通过。新增 `daily-transfer-security.test.ts` 实测AA密码单独不能放行、800元后再转200/200.01/300元、跨卡并发确认与扣款事务复核、黄单风险升级、定时任务补验证后完成、UTC+8跨日边界。保留超过3000元与可疑收款人的密码加指定生物因子限制。
- 最终验证：39个测试文件、401项回归通过；生产构建与类型检查通过。414×896手机尺寸实测200元人脸单方式、3001元密码加指纹、异常短信入口缺席、白底文档及取消保留对话。对照图：`.scratch/verification-v2-reference-default.png`、`.scratch/verification-v2-reference-keypad.png`、`.scratch/verification-v2-reference-methods.png`。独立资金账户仍可用短信/生物识别演示完成常规转账，不要求凭空生成卡密码。
