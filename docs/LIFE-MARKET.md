# 生活商城与订阅管理

生活页使用现有 Base UI、Motion 和主题色。桌面宽屏显示两列横向商品卡片，窄屏自动调整为单列横向或手机双列卡片；Agent 仍使用现有浮窗。

- 商城：购买经核对和独立安全验证后，立即从本人正常状态储蓄卡扣款。订单、银行流水及扣款在同一数据库事务中保存，支持刷新和跨设备查询最近100笔订单。旧版浏览器中的演示订单不转换为已付款订单。
- 配送：支持立即送出（预计48小时送达）或预约送达（北京时间至少48小时后、90天内）。订单展示付款卡、收件信息、预计发货与送达时间、物流及退款进度。
- 退款：预约订单未发货时可即时原路退款；发货后至预计签收后7天内可申请退货，24小时模拟验收后退款。退款流水关联原扣款，重复确认、申请或后台重试不会重复扣款或退款。超期需人工处理。
- 订阅：核对并验证后扣首期费用，默认只开通一期。自动续费必须明确授权，月费最多11次、年费最多1次，授权最多366天，确认单展示每次金额及累计上限。已有有效期的同一服务不能重复开通扣款。
- 我的订阅：读取本人已登记订阅，展示状态、付款卡、已付费有效期、下次扣费、剩余授权次数和费用汇总。取消经确认流程停止后续扣费，保留已付费有效期，不退当期费用。单期服务不会显示虚构的续费日期。历史导入订阅的外部权益以原服务商为准。
- 保留生日计划、AA 收款、任务中心和 Agent 订阅识别/续费提醒入口。
- 商品插画为本地 SVG，无外部图片请求。新增商品可复用 `LifeProduct` 数据、商品卡片和详情弹层。

## Agent 与跨场景任务

Agent 与原生页面共用受控银行工具：`list_life_catalog`、`buy_life_product`、`list_life_orders`、`return_life_order`、`subscribe_life_service`、`list_life_subscriptions`、`cancel_subscription`。查询仅返回本人数据；所有写操作必须通过确认和权限策略。购买、订阅沿用独立安全页，密码不进入 Agent 对话。

生日送礼等任务可在已有 DAG 中组合查询联系人、挑选商品、预约配送和购买；收件人、手机号、地址、付款卡及时间缺失时必须询问，不允许猜测。购买节点暂停等待用户确认与安全验证，执行后继续任务。物流和会员权益使用文财沙箱服务，不代表真实商家发货、真实快递或第三方会员开通；本系统内的余额扣减、退款和银行流水为实际持久记账。

## 后台运行

启动现有 `pnpm worker`，按模拟银行时钟处理配送状态、到期退货退款、订阅续费和提醒；管理员“执行到期任务”也调用同一处理逻辑。仅查询订单不会发起扣款。续费金额变化、余额不足、银行卡不可用、用户锁定、授权到期或错过24小时扣费窗口时暂停续费并通知，不追扣历史费用。已取消及单期服务不会继续扣款或生成续费提醒。

新增表 `bank_life_orders`、`bank_life_subscriptions` 首次使用时非破坏性创建，保留原有账户和历史订阅。金额取自服务端商品目录，不能由前端或模型指定。确认执行时重新检查价格、余额、银行卡状态与支出限额；后台授权也受额度和状态约束。

## 验证

`tests/life-commerce.test.ts` 覆盖真实扣款与独立验证、并发重放、价格篡改、余额不足、冻结卡、跨用户隔离、即时/延迟退款、7天边界、续费次数与到期、重复订阅、取消和旧订阅入口、北京时间月末周期，以及生日 DAG 暂停确认后继续执行。配合原有 API 权限、策略及全量测试回归。真实模型在隔离数据库上检查购买、订阅、订单/有效期查询、退款及取消工具调用；未确认的模型操作不得改变余额。

2026-10-16 验证：类型检查、生产构建及全量53个测试文件、569项测试通过。浏览器使用独立数据库，在1840px桌面和430px手机宽度实际完成预约购买39元商品、原路退款39元、开通15元单期订阅及取消订阅；核对银行流水、退款关联、服务有效期及无后续扣费，手机无横向溢出。真实模型核对购买、退款、订阅开通与取消回执，无数字核验拦截。实测修复日期控件输入未同步的问题，以及退款/取消安全页错误显示新卡密码设置文案的问题。
