# 基金数据、未知价申购与只读理财专家

2026-10-22更新。独立理财页与九周期指标口径见 [WEALTH-MARKET.md](WEALTH-MARKET.md)。数据来自公开基金净值；所有订单只在文财模拟银行记账，未接入真实基金销售或清算机构。当前阶段实现申购，赎回留待后续接入，不能调用原有银行理财赎回工具代替。

## 启动与断网演示

开发时在 `.env.local` 配置 `FUND_DATA_MODE=live`，使用 `pnpm dev` 会读取配置并同时启动web与worker。部署环境可单独运行原有 `pnpm worker`，此时须由进程管理器或shell注入环境变量，不能只修改一个未被加载的env文件。worker启动时刷新一次，在北京时间20:00–23:59按每只基金30分钟间隔重试，数据请求不阻塞其他银行自动任务。web页面、Agent只读缓存，不在查询时等待外网。

可选 `FUND_DATA_MODE=cache`（禁止联网，空库从离线快照初始化）或 `fixture`（worker读取快照）。未配置默认live。断网时保留最后一次有效数据；空库也可以使用 `fixtures/funds/*.json`。原4只快照采集于2026-10-21、新增17只采集于2026-10-22，分别保留各自净值日；新增净值截至2026-10-21或22，包含成立以来已取得历史，不改写日期。页面明确显示来源、净值日和过期状态；超过三个工作日没有新净值时拒绝新申购，现有订单与持仓仍可查询。

演示部署保留 `AUTH_DEMO_MODE=true` 才能使用模拟指纹/人脸；这不是生物识别。生产业务需替换真实认证适配器。基金红色确认沿用原有交易密码加额外验证规则。

断网可演示查询、专家代码回退和“扣款后待确认”的真实订单状态。如果离线快照没有交易日之后的净值，订单会继续等待，不能拿旧价格制造确认成功。自动化测试用明确标记的测试净值验证T+1结算，不修改公开快照日期。

## 数据接口与边界

- `src/server/funds/provider.ts` 定义 `FundDataProvider` / `FundSnapshot`。`EastmoneyProvider` 默认联网，`FixtureProvider` 提供可打包的离线实现；Tushare可通过同一接口后续接入，目前没有启用Tushare或存储其token。
- 白名单在 `pool.ts`，当前21只非货币基金（含8只债券型基金）。名称必须完全匹配，R1–R5由人工配置，是演示适当性分级，不是从基金类型或收益率推断的销售机构评级。名称变化会隔离基金，成功重试也不会自动解除，须人工核对。
- 默认从`pingzhongdata`文本正则提取名称、费率、起购金额、单位/累计净值数组及日涨跌幅，以`JSON.parse`解析数组。**绝不eval、新建Function、导入或执行远程JS**。脚本源不可用时尝试东方财富 f10/lsjz 最新20条JSON，与完整离线历史合并；实测较大的pageSize可能返回 Data:null。两者属于同一数据生态，并非独立供应商。兜底无法更新费率时暂停新申购，只提供查询；申赎状态仍由公开页面核对，取不到时保留现有缓存。
- 每请求最多2MiB、适配器12秒超时、外层刷新15秒截止、全局每秒最多发起一次请求。每只基金有数据库租约，过期worker不能落库。完整响应先通过Zod、白名单、实日期、非未来日期、严格递增、净值和费率范围校验，**之后才开启数据库事务**。失败不清空缓存。
- 新表自动`CREATE TABLE IF NOT EXISTS`，不会重置现有账户。`bank_funds`、`bank_fund_navs`、`bank_fund_sync_state`、`bank_fund_orders`、`bank_fund_positions`的Drizzle定义在`db/fund-schema.ts`。

## 交易与估值

1. `preview_fund_order`校验风险测评一年有效期、等级、净值新鲜度、申购状态、起购额、付款账户、卡状态和限额，签发15分钟参数绑定的预览令牌，不扣款。
2. `commit_fund_order`始终红色，走原有确认卡、独立安全页面、强验证和渠道交接。执行前在数据库事务内重新检查全部前置条件，原子消费令牌、扣款、生成理财流水、保存`submitted`订单与审计。actionId唯一，同一操作重试不会再扣。
3. 北京时间15:00前交易日取当日，15:00及以后取次一自然日。worker只读取本地净值，找**第一条日期不早于交易日**的公布净值，且当前本地日期已晚于该净值日，才确认T+1份额。无需交易日历，周末和假期自然等待下一条净值。没有合格净值就等待，不拿最近旧净值成交。
4. 金额用分、净值用万分之一、份额用百分之一；BigInt计算，净申购金额按外扣法四舍五入到分，份额向下取到0.01份。申购费在下单时冻结，不因之后的费率变化被改写。
5. 待确认申购款计入资产；确认后按最新净值估值计入总资产和#7画像风险结构，避免扣款后资产消失或本金、份额双算。没有净值只显示成本估值标记。基金流水分类“理财”，不污染月均消费。
6. DAG失败可补偿未确认订单，同一退款只执行一次；份额已确认时转人工，不能自动伪造反向成交。当前没有用户基金赎回接口。

## 专家边界

`get_wealth_advice`是green/read工具，不产生待确认单或交易授权。它复用#7 `computeProfile`的完整月份月均支出，预留六个月生活费，并扣除信用卡未还余额；可用现金只计算正常储蓄卡，已冻结的生日专款已从现金扣除，不重复扣。少于三个完整月份时提示资料不足，不以零消费当作可投资全部余额。

风险评估失效返回`needs_risk_assessment`；缺期限或流动性返回`needs_information`，Agent使用现有选择题组件收集。投资金额和目标百分比必须出自当前用户原文，不能由模型猜测。代码过滤风险、金额、期限/流动性、数据新鲜度，复用统一收益算法计算阶段收益、年化波动率和最大回撤，检测需求冲突并排序，最多送五个匿名候选给模型。

模型只能看到`候选1`等别名、数字和枚举，看不到基金/银行产品名称、编号、交易备注、原始用户自由文本。模型最多选三项并写理由。服务端验证输出结构、候选范围与唯一性、禁用承诺词；金额必须在当前预算或该候选起购额中有出处，百分比必须属于**该候选**指标，关键指标标签也与对应值核对。失败、超时或离线均整体回退代码文案，真实名称最后由服务端恢复。选择“随时可用”时不会承诺基金即时赎回到账。

百分比核验只在`funds/advice.ts`内启用，**没有扩展主对话`verify/numbers.ts`**。专家审计记录`wealth_advice`，保留候选、实际选择、预算、冲突与文案来源。对外展示历史业绩与数据日期，不给模型分配真实资金或承诺未来收益。

## 使用入口与验证

理财页“我的理财”支持基础目录、详情、持仓/订单和手动申购。申购仍使用统一`PaymentApproval`；“问理财专家”将请求发给Agent。Agent工具包括`list_funds`、`get_fund_details`、`get_fund_portfolio`、`preview_fund_order`、`commit_fund_order`、`get_wealth_advice`，新增 `rank_funds`、`get_fund_metrics`。基金查询和专家结果使用固定只读组件，按钮只发送完整查询消息，保留历史按钮。

新增测试：`fund-data.test.ts`、`fund-trading.test.ts`、`wealth-advice.test.ts`、`wealth-analytics.test.ts`。所有资金测试使用独立`.scratch`数据库，覆盖恶意JS不执行、校验拒写、断网缓存、名称隔离、租约、红色完整验证、未知价/15点/周末/T+1、重试和退款幂等、执行前状态变化、画像月均支出、资产估值以及专家匿名化/数字/百分比/保证词回退。
