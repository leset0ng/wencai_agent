# 后台收款账户风险分析（handoff #1）

## 行为与边界

后台 worker 异步分析文财内部收款账户的交易特征。AI 只能提出「疑似」标记，不能决定权限等级、确认高危、解除标记或执行转账。前台转账路径只查询已经落库的标记，不等待模型。

| 标记 | 代码策略 | 后台人工操作 |
| --- | --- | --- |
| 无活动标记 / 已解除 | 原有日累计、新收款人、夜间、熔断等规则继续生效 | 已解除记录保留 |
| 疑似 `suspected` | 升级为红色强验证，提示核实收款人身份 | 确认高危或解除 |
| 人工确认 `confirmed` | 拒绝向此账户转账 | 可人工解除 |

后台入口为「收款风险复核」，路由 `/admin?userId=<已存在用户>&section=risk-review`。复核列表是全局视图；数字来自服务端聚合，理由来自固定枚举文案。用户注册天数不是银行卡开户天数，缺失时显示未知。

## 数据、调用与安全

`src/server/risk/accounts.ts` 用 SQL 计算近 24 小时入账笔数/金额、不同付款用户数、出账金额、两小时内快速流出比例，以及认证用户注册天数。不同付款人由 `bank_transfer_links` 的真实双边流水关联确定；排除同用户互转、冲正及未来流水。对手名称、备注、商户、账号、账户 ID 均不传给分析模型。

当前候选筛选条件同时满足：至少 5 笔入账、3 名不同付款人、入账合计 1000 元、快速流出比例 70%。这些条件用于限制分析开销，**不构成自动拒绝策略**。模型仅可输出严格 JSON `suspicious` 与枚举 `signals`；不接受模型风险等级、自由理由或多余字段，信号还须与 SQL 特征相符。

每轮有界扫描并最多调用 3 次模型；每次最多等待 8 秒。持久租约防止多个 worker 重复分析；普通扫描结果短暂冷却，成功分析冷却 45 分钟，失败冷却 15 分钟，同一活动快照不重复收费。分析在银行业务 tick 之外运行，故障不会阻塞正常转账或到期任务。未配置模型或模型超时仅记录固定错误码，不删除已有标记，也不把原始模型错误写入审计。

AI 写入与人工复核均和审计同事务提交。复核使用记录版本防止旧页面覆盖新决定；人工解除保存当前活动快照，迟到的 AI 输出和相同历史活动不能重新挂标。新活动可触发新的分析与新版本标记。

`/api/admin-risk` 使用现有后台启用开关和访问凭据，先鉴权后读写。复核人由服务端生成，客户端不能提供 `reviewer`、`userId` 或任意状态。现有后台凭据是演示管理入口，不是完整的管理员角色系统。分析、复核接口没有注册到用户 Agent、飞书或 MCP 工具集中。

## 确认与自动执行

`collectFacts()` 按收款人、账号、本人的目的账户或 AA 请求解析真实收款账户，`recipient-account-risk` 规则负责升级/拒绝。查询标记不能通过换一个同账号的旧收款人、缺少关联记录或模型伪造参数绕过。

已有确认单执行前重新读取标记；新增标记版本先更新核实提示并要求再次确认，再接受强验证。即使旧卡片已经是红色，也必须展示新原因。结算扣款事务内再次检查标记，防止短信/Passkey 验证期间人工复核或 AI 更新形成竞态。

自动转账授权保存用户核对过的具体账户与标记版本。新增风险不会因为旧授权本来已是红色而自动放行：单次预约进入待核对，定期授权暂停且不消耗次数与金额。用户明确核对当前标记并强验证的新授权仍可正常执行；版本再次变化时重新核对。人工确认高危始终拒绝。

相关扩展表均为幂等、无损升级：`bank_risk_flags`、`bank_risk_analysis_state`、`bank_pending_risk_snapshots`，以及自动任务/定期授权的可空 `payee_risk_json` 字段。不会重播种或覆盖原账户余额。

## 演示与验证

合成演示数据必须显式追加，建议使用独立数据库：

```powershell
$env:DATABASE_URL = 'file:./.scratch/risk-demo.db'
pnpm exec drizzle-kit push --force
pnpm exec tsx src/server/db/seed.ts
pnpm exec tsx scripts/seed-risk-demo.ts --append-demo
```

上述初始化和播种仅用于新建的演示库。追加脚本可重复执行，不修改原有用户账务；它生成可辨认的 7 个合成账户、6 笔双边转账。启动 `pnpm dev` 后等待异步分析，再到后台复核。只有模型输出疑似，才会生成待复核标记；数据不是真实欺诈结论。

2026-10-13 完整回归：**35 个文件、339 个用例通过**，使用独立 `.scratch/risk-final-regression-20261013.db`。类型检查与生产构建通过。新增用例覆盖模型输入隔离、冲正/未来流水、超时/失败、61 个普通候选后的扫描公平性、人工复核与 AI 竞态、真实双进程冷却保护、审计回滚、现有确认单提示、各转账路径、旧自动授权、后台鉴权与版本冲突。

实际演示库也验证了：AI 生成疑似标记 → 旧黄色确认单显示新警告并升红 → 人工确认高危 → 转账拒绝且无扣款 → 人工解除。审计链完整，浏览器无新增错误。

异步标记存在时间差；尚未分析的第一笔仍依赖原有新收款人、金额和频率规则。旧流水缺少双边关联时不会用自由文本猜测付款身份。当前覆盖文财内部可观测账户，未接入外部银行反欺诈数据；这是一套演示风控线索机制，不能声称识别所有欺诈。
