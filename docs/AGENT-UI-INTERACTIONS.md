# Agent 展示、选择与问卷

## 展示与选择

- 只读银行卡：`AgentCardDisplay`，复用 `BankCard` 和 `Carousel`，仅展示备注、脱敏尾号、状态、余额或可用额度。无选择、确认、取消、卡号眼睛按钮；多卡支持滑动和方向键浏览，单卡不显示切换提示。
- 模型调用 `display_bank_cards` 可按真实 `cardIds` 或 `limit` 指定显示范围；服务端只返回本人的卡，未知或他人卡ID拒绝。前面的全卡查询不会覆盖指定单卡展示。
- 生成式目录提供 `CardDisplay {title,data:$state引用,cardIds?}`。卡ID必须存在于对应工具数据，金额不能由模型传入。
- `displayPurpose` 根据当前需求和本轮模板区分只读查询、业务选择、风险测评。查询表格无操作列；风险测评不显示理财产品选择。`Table.selectable` 默认关闭，真实选择场景才开启。

## 逐题问卷

- 通用 `ask_questions`：模型设计1—12题，每题2—6个单选项。`AgentQuestionnaire` 支持上一题、下一题、答案保留和最后统一提交。选项及题目切换不发消息，最后才以用户身份发送完整题干、选项、答案值和业务说明。历史问卷仍可修改、重提，多个问卷单选分组互不干扰。
- 标准风险测评：`get_risk_questionnaire` 返回 `risk-profile-v1` 五题问卷。收到全部答案后 `assess_risk_profile` 只试算；登记仍由 `commit_risk_assessment` 生成单独确认单，不能通过答题直接登记。
- 问卷不收集密码、验证码、完整卡号或身份证号。重复题号、重复选项、缺失答案和篡改标准风险题目均拒绝。
- 通用问卷无需 `prepare_interaction` 或 `show_view` 包装，正文不重复展开整套题目。

## 完成状态与文字

- `ConfirmCard` 收到独立安全页的成功回执后，本地成功状态优先于外层尚未刷新的失败状态；`PendingControl` 同时刷新确认状态缓存，保留原摘要。取消验证不显示成功，历史“核对结果”“重新办理”仍保留。
- `AssistantText` 接入中文标点兼容 Markdown 解析，支持对真实金额、风险等级和结论局部加粗。完整回答采用静态解析，流式阶段采用流式解析；清理末尾孤立的粗体标记时保留正常粗体、脱敏卡号和代码。

## 回归验证

`tests/agent-ui-modes.test.ts` 覆盖查询/选择分离、指定卡展示、生成视图的数据约束、问卷协议和中文强调。`tests/agent-ui-dom.test.ts` 通过实际组件点击验证确认状态竞态、关闭验证、逐题切换与最终提交、历史答案修改和问卷之间的独立性。真实模型在隔离数据库检查单卡查询、两卡展示、重新测评、通用三题问卷及答案试算，所有查询与答题均未改变余额。

本次全量55个测试文件、584项测试通过，类型检查与生产构建通过。恢复浏览器连接后，在430px手机宽度检查实际只读单卡（操作按钮数为0）、中文金额加粗和五题逐题交互；网络记录确认选题与下一题期间没有聊天请求，最终提交仅发送一次聊天请求，模型只试算并询问是否登记。问卷无横向溢出，历史提交按钮仍保留。浏览器使用独立模拟数据库。
