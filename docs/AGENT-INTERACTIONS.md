# Agent 可复用选择交互

多笔转账使用只读 `prepare_transfer_batch` 和 `BatchTransferView`，每笔独立消歧、共用付款卡及统一确认。接入与验证见 [BATCH-TRANSFERS.md](BATCH-TRANSFERS.md)；下方 `prepare_interaction` 协议仍用于单步交互。

## 界面与接入

`src/components/chat/AgentInteraction.tsx` 提供统一入口。新增功能优先引用以下组件，不再为每个工具编写单独的发送回调：

- `AgentInteractionGroup`：每套交互的草稿容器。收集所有选择组件，去重，并提供一个统一确认入口；银行卡存在时确认入口放在银行卡区域。`ChatView` 为每条助手回复接入。
- `AgentCardPicker`：复用账户区域的 Embla `Carousel` 和 `BankCard`。单卡、箭头、圆点、滑动；当前显示卡即待确认卡，底部只保留“取消”和“确认”。不再有“选择”按钮。`role="source"` / `"target"` 明确付款卡/收款卡；缺省时根据当前问题和办理需求推断。
- `AgentChoiceList`：收款人、订阅、其他项目，展示名称、明细及选择按钮。
- `AgentSelectableTable`：表格自动识别真实记录，为每行添加选择按钮；全部为银行卡时自动复用轮播。
- `AgentActionButton`：有 `choice` 时只修改本地草稿；不会发送消息。无选择项时通过 `AgentSelectionConfirm` 显示确认入口。
- `AgentSelectionConfirm`：唯一提交入口，汇总同一套交互内的所有对象、付款卡、产品等条件后发送完整消息。未选齐时禁用。

普通固定工具回执在 `ToolPart.tsx` 接入。生成式界面使用 catalog 中的 `CardPicker`、`ChoiceList`、`Table`；无选择项的办理流程使用 `Confirm`。选择区域已自动提供确认，不重复添加 `Confirm` 或旧 `FollowUp`。数据通过 `$state` 引用服务端工具结果，不能由模型内联伪造。未来记录具有稳定 `id` 与 `name` / `title` / `label`，即可复用列表或表格；特殊字段通过 `AgentChoice.details` 提供中文标签。

`AgentInteractionContext` 由 `ChatView` 为各条回复提供。选择不调用 `send()`；确认才发送意图，文本本身不会授权交易。唯一对象自动确定并灰显；收款人/产品多对象选中后灰显。银行卡按当前轮播页确认，切卡不会发消息；确认后卡片灰显。取消只清除本组草稿并提示，可再次调整确认，唯一对象仍自动确定。轮播、显隐、停止回答、独立安全页密码/验证方式均不进入模型。

## 完整消息与任务隔离

2026-10-14起，按钮消息由Agent在生成当前界面时声明语义模板，组件按固定句型代入当前选择。旧的 `【办理需求】/【已选条件】/【交互说明】` 历史格式只做兼容读取，不再作为新消息输出；不重发原始用户复合需求，不把其他转账、订阅或已完成步骤拼回来。

1. Agent调用只读工具 `prepare_interaction`，或在 `show_view.spec.interaction` 顶层填写模板。普通工具自动展示的选择区域也要在同一回复声明模板。
2. 格式为 `{version:"1",intent,fields}`。意图限转账、申购、赎回、取消订阅、卡片操作、查询、仅选择；每套界面只对应当前一个步骤。
3. 实体输入用真实工具对象的 `$state` 引用，金额来自本轮明确用户需求或本轮实际完成工具的办理金额字段。旧轮预览金额不能未经本轮佐证直接复用；拒绝自由正文、未知字段、密码/验证码/令牌引用及“验证已通过”断言。
4. 服务端解析为 `ResolvedInteractionTemplate`。`messageInteractionTemplate()` 只取当前助手回复的有效模板，`confirmationMessage()` 用 `renderInteractionTemplate()` 的固定句型填入当前所选实体，不从旧需求推测金额。当前选择可替换卡片、收款人、产品等实体，不能改写模板金额、操作或备注。
5. 没有合法模板的旧界面仅发送当前选择事实并询问缺少的目的/金额，不退回复制历史。字段未齐全的模板明确要求先询问，不创建交易。

例如：`我确认从「储蓄账户（储蓄卡，尾号4267）」向「王方（银行：招商银行；收款账号：6214 **** 2222）」转账600.00元，备注「生活费」。请核对当前银行数据并生成本次操作的确认单，仍须在独立安全页面完成验证。`

`SelectionDraft` 属于当前交互组，所有选择组件共享它；确认前不写入 `InteractionMemory`。旧按钮绑定它所属回复的模板，仍可重选/取消再确认，另一回复的金额和收款人不能替换它。只发送当前步骤所需的公开实体信息，不附带余额、产品收益、无关订阅或完整卡号。反复确认不会递归增长消息。

按钮不被消费或删除。Agent 回复期间暂时禁用；回复结束、停止回答、取消独立安全页后重新启用。此前已取消/已过期/已完成的确认卡保留“核对结果”和“重新办理”，后者发送完整新意图、重新查询并生成新的确认单，不重放旧确认单。

## 确认与服务端边界

- 本地统一确认后，Agent 根据全部已选条件重新查询，生成服务端银行确认单。
- 银行确认单中的确认：发送 `operationMessage()`（仅本张服务端摘要的固定短模板），附 `verificationActionId`，打开独立安全页。不附加用户原话或历史选择；不能被别处未提交的草稿改变参数。银行确认单存在时隐藏本轮重复选择组件。
- 点击取消：发送完整取消消息，附 `cancelActionId`。`resolveInteractionCommand()` 检查用户归属，幂等取消对应待办及计划；已完成操作只核对，不逆转交易。
- 安全页成功：自动读取服务端摘要，再发送“请核对以下操作的服务端结果…”及 `confirmedActionId`，只核对实际执行回执。核对、取消、重新办理都只包含对应银行确认单的摘要，不复制其他步骤。
- 验证/取消消息直接按服务端状态生成反馈，不启动模型、不创建新交易；成功后的自动核对交给既有只读回执轮次，禁止模型顺势创建新写操作或新计划。重新办理不携带旧动作命令，仍经过新的确认和验证。
- 黄色常规验证保留“使用其他方式验证”；红色验证直接展示额外验证，不再折叠在该入口下。日累计含本笔超过1000元或AA基础红色操作，有卡时要求卡密码加额外强验证，可使用短信或模拟指纹/人脸；单笔超过3000元或收款人异常时第二因子仅接受指纹/人脸。独立安全页与确认执行均重新判定最终等级。演示凭据仍受 `AUTH_DEMO_MODE`、用户/动作/方式绑定、过期与一次消费限制。

## 检查

### 2026-10-14 Agent语义模板与历史复放修复

原按钮消息把用户的复合需求逐次拼回，银行确认按钮又在本张摘要后附加旧需求，导致600元确认中重复出现5000/6000元和无关订阅。现统一采用Agent声明的当前步骤语义模板，银行操作按钮只用本张服务端摘要。新测试 `interaction-template-contract.test.ts` 与 `interaction-message-template.test.ts` 覆盖未知字段/凭证/验证断言拒绝、本轮金额来源、旧预览金额隔离、当前卡替换、旧按钮归属、模板缺失降级、卡片管理与赎回角色及PAN脱敏。

最终检查：43个文件、475项回归通过，类型检查及生产构建通过。真实DeepSeek通过现有工具链生成600元转账模板；一次错误视图数据路径被拒绝后自行修正，模板条件保持不变。浏览器414×896检查中，切卡/取消为0条消息，确认才发送1条完整单步消息，重复确认内容一致；旧复合需求的其他金额和订阅未进入消息。截图 `.scratch/interaction-template-final.png`；模型验证记录 `.scratch/interaction-template-model-proof.json`。测试使用隔离库与独立组件检查页，不执行用户真实转账。

### 2026-10-13 选择/确认统一修订与溢出原因

原 `.bank-gen-children` 是未设置列宽的 Grid，子组件默认 `min-width:auto`；银行卡轮播的百分比宽度与不换行内容贡献最小内容宽度，撑开网格。414px 手机复现中，外层内容为382px、网格可用346px，实际列宽却达到794px，底部按钮也随父级扩到768px，确认入口被推到屏幕右侧。此前仅测试非嵌套选卡区，漏掉该路径。

修复为 `minmax(0,1fr)`，约束网格子项、轮播、卡片与按钮 `min-width:0` / `max-width:100%`，并对小容器内的卡号字体与内边距自适应。相同复现网格恢复346px、按钮区320px；320px窄屏也完整展示确认入口。

`selectionView()` 删除旧的按尾号付款 FollowUp 和空 Panel，合并只包一层选择组件的外框。同一交互组根据角色和记录 ID 去重。已生成银行确认单时不再展示可改变参数的重复选择区。新增流程复用同一组和确认组件即可。

`canonicalChoiceGroups()` 将同角色的多份卡片查询合并为唯一轮播，优先使用可用卡片子集；确认只读取可见轮播的 `currentChoice`，隐藏的重复组件不能覆盖它。付款卡/收款卡分开处理；不相交候选合并，避免丢失选项。

真实对话中还复现了说明文字里的转账意图金额、验证门槛触发数字校验兜底。服务端仍拦截该正文、保留审计；当前轮已展示真实选择/银行确认组件时，只隐藏重复的固定兜底提示，不展示被拦截的正文。无真实组件时仍保留提示，银行业务错误也不受影响。

`agent-interactions.test.ts` 覆盖完整消息、旧按钮任务隔离、同一任务共享选择、同类条件覆盖、密码排除、通用新增类型、真实数据引用以及重复表格折叠。`agent-presentation.test.ts` 覆盖银行卡/关联账户重叠展示，余额变化及独立账户保留。`per-card-security.test.ts` 覆盖跨用户取消拒绝、验证消息只读和取消幂等，以及既有单/双因子安全规则。

浏览器使用 `.scratch/per-card-preview.db` 隔离库。新版专项确认：选择、切卡、重选均不增加消息；统一确认只新增一条完整消息；唯一对象灰显，多对象可替换；无选择项仍有确认入口；窄屏和嵌套布局不溢出。截图在 `.scratch/selection-*.png`。所有测试不写入原用户数据库。
