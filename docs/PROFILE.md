# 后台用户画像（#7）

> 2026-10-13。后台人员查看单个用户的收支、资产与风险偏好。**只读，不影响任何交易的风险判定。**

## 一句话

**数字由代码算，文字由模型写，文字里的金额要过核验，过不了就换成规则文字。**

## 入口

- 后台 `/admin` → 选用户 → **用户画像**（`section=profile`）
- 列表：所有用户的月均收支、储蓄率、总资产、特征标签。**不调用模型**。
- 详情：指标卡、支出结构、近 6 个月支出、固定支出、理财与风险、一段文字摘要。

## 结构

```
profile/profile.ts
  collectProfileInput()   读库：流水（近 6 个月）、持仓、产品、订阅、卡片、测评
        │
  buildProfileMetrics()   纯函数：输入数字快照 → ProfileMetrics（可单测、可复算）
        │
  deriveTags()            纯函数：由指标推导标签，每个标签带"依据"一句话
        │
  narrationInput()        白名单化 + 预先格式化：模型唯一能看到的东西
        │
  narrateProfile()        模型写摘要 → 结构/长度/金额出处检查 → 通过用 AI 文字，否则用规则文字
        │
  getUserProfile()        按指标指纹缓存文字；写缓存与审计同一事务

routes/api/admin-profile.ts   GET only：无参数=列表，userId=详情，refresh=1 重写文字
components/admin/views/Profile.tsx   列表 + 详情
```

`bank_profile_narratives` 缓存的是**文字**，不是指标。指标每次重新计算，`fingerprint` 是指标的哈希：数据变了指纹就变，旧文字不会冒充新数据。

## 指标口径

| 指标 | 口径 |
|---|---|
| 观察月数 | 近 6 个月里**有流水的完整月份**（不含当月）。少于 3 个月时比率类指标输出"数据不足" |
| 月均收入 / 支出 | 观察月份的平均。当月未结束，不参与均值，但单独列出 |
| 排除项 | `理财`、`opening`、`冲正`、**本人账户之间的互转**；信用卡还款不计为支出（消费已在信用卡流水里计过） |
| 对外转账 | 计为支出 |
| 储蓄率 | (月均收入 − 月均支出) / 月均收入；数据不足或收入为 0 时为空 |
| 活期可覆盖月数 | 活期余额 / 月均支出 |
| 固定支出 | 同对手方、同金额、**按月连续**至少 3 个月，且最近一次不早于上个月；定额转账（房租）算，AA 不算 |
| 持仓与测评 | 持仓最高风险等级高于测评等级为 `mismatch`；未测评或无持仓为 `unknown` |

口径与后台总览（`admin/utils.ts` 的 `cashFlow`）一致，同一个用户在两个页面上的数字能对上。**与用户端首页（`dashboard.ts`）不完全一致**：首页只排除信用卡还款。这是已有的差异，不是本次引入的。

## 红线

1. **画像不进入策略引擎、不进入 Agent、不作为数字核验的证据。** `bank_profile_narratives` 只被 `profile/` 与 `db/schema.ts` 引用；`tests/profile-db.test.ts` 扫描全部源码守住这一条，并已验证：往 `agent/tools.ts` 加一行引用，测试立刻变红。如果将来想让画像参与风控，必须像 #1 那样走"事实 → `rules.ts`"，不能读这里的文字。
2. **模型看不到外部可控文本。** `narrationInput` 没有姓名、账号、对手方名称、备注、商户名；支出类别经过白名单。测试用带注入语句的对手方和类别验证这些字样不会出现在输入里。
3. **模型的文字不能成为证据。** 金额核验的出处只有交给模型的那份数字和同口径的指标金额，模型自己写的文字不会成为出处。
4. **画像只读。** `/api/admin-profile` 没有 POST；与 `admin-risk` 一样用后台鉴权，用户 Cookie 读不到。

## 实测中发现并修掉的问题

接手时最该知道的部分：这些都是在真实模型和浏览器里才暴露的，单测一开始没抓到。

| 问题 | 原因 | 处理 |
|---|---|---|
| 摘要总被判"格式不符"而回退 | 完整输入下模型把每个字段都复述一遍，超过 260 字上限 | 提示词要求"挑 2–3 个点，不超过 120 字" |
| 摘要里出现 `mismatch`、"储蓄率 0.294" | 输入里直接给了小数和英文枚举，模型原样照抄 | 输入侧把比率、枚举预先转成中文文本（"29.4%"、"持仓风险高于测评"），模型不需要也不应该自己换算 |
| 摘要写"信用额度使用率为 0.0%"，而用户根本没有信用卡 | 输入里给了"无信用卡"，模型自行补全成了数字。**不涉及金额，数字核验拦不住**，但是不实陈述 | 没有意义的字段**整个不交给模型**，不给"无""数据不足"这类占位让它发挥 |
| "电商平台 ¥1,800 / 月，连续 3 个月" | 我按"出现过 3 个月"识别，隔月出现的也算 | 改为按月连续 |
| 房租被排除在固定支出之外 | 我把"转账"类整体排除了 | 只排除 AA；定额转账算固定支出 |
| `?section=profile` 打开后落在「账户总览」 | `routes/admin.tsx` 里有一份手写的 section 白名单，类型检查抓不到（它是字符串数组） | 白名单改为从 `navigation` 推导，新增后台页面只改一处 |

## 已知边界

- **数字核验只管金额和卡尾号**（`verifyNumbers` 只校验带 ¥ 或"元"的数字）。模型写"约三万多"这类不带精确数字的表述不会被拦。画像里摘要旁已标注"仅供后台参考"。
- **固定支出的定义是字面的**：每月分毫不差的餐饮也会被算作固定支出。真实用户很少如此，但识别不是语义判断。
- **摘要是模型写的，同样输入可能有不同措辞**（温度 0.2）。缓存按指纹保证"数据没变就不换文字"；点"重写摘要"会换。
- 画像按**用户**而非账户统计；多账户用户的互转识别依赖 `bank_transfer_links`，没有该记录的老流水不会被识别为互转。
- 列表每次打开会为每个用户重算指标，用户量大时会慢；演示规模够用。
- 没有做"画像变化提醒""画像导出"，也没有把画像用于推荐或营销，那是另一类决定。
